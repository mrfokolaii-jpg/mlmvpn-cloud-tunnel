# تونل من — آزمایش VPN با GitHub Actions

این مخزن سورس یک **اپ اندروید آزمایشی** و عامل سمت سرور را دارد: ورود از صفحهٔ رسمی GitHub، انتخاب کشور و دکمهٔ شروع/قطع. هر شخص می‌تواند با **حساب دلخواه خودش** وارد شود؛ حساب صاحب این سورس حساب اجباریِ اپ نیست. با تأیید جداگانهٔ کاربر، اپ یک مخزن خصوصی جدید در حساب همان کاربر می‌سازد و فایل‌های عامل و workflow را در آن قرار می‌دهد.

> **مهم: نامحدود واقعی نیست.** هر job روی رانرهای میزبانی‌شدهٔ GitHub حداکثر ۶ ساعت اجرا می‌شود. این پروژه هر نشست را حدود ۳۳۵ دقیقه نگه می‌دارد و قبل از پایان برای نشست بعدی تلاش می‌کند، اما صف، سهمیه، هزینه، محدودیت شبکه یا سیستم‌عامل می‌توانند اتصال را قطع کنند. دو نشست ممکن است هنگام تعویض مدتی هم‌زمان اجرا شوند و هر دو سهمیه مصرف کنند. رابط شمارشگر زمان نشان نمی‌دهد، اما محدودیت‌ها همچنان وجود دارند.
>
> GitHub Actions برای توسعه و آزمایش است. استفادهٔ دائمی از رانرهای GitHub به‌عنوان VPN ممکن است با [شرایط GitHub Actions](https://docs.github.com/en/site-policy/github-terms/github-terms-for-additional-products-and-features#actions) ناسازگار باشد و به محدودیت یا تعلیق حساب منجر شود. برای سرویس طولانی‌مدت، سرور مستقل مناسب‌تر است. این کد فقط برای آزمایش ارائه شده و امنیت و پایداری آن روی دستگاه واقعی هنوز تأیید نشده است.

در هر لحظه فقط **یک** VPN فعال است، اما می‌توان چند حساب GitHub را روی همان دستگاه نگه داشت و بینشان جابه‌جا شد؛ هر حساب توکن رمز‌شده، مخزن و وضعیت سلامت جداگانه دارد. اگر GitHub صریحاً پاسخ بدهد سهمیهٔ Actions یک حساب تمام شده، اپ آن را علامت می‌زند و حساب سالم بعدیِ دارای مخزن آماده را امتحان می‌کند. برای کمینه‌کردن مجوزها اپ دامنهٔ گستردهٔ `user` و endpoint خصوصی billing را درخواست نمی‌کند؛ بنابراین خطای مبهم یا اجرای ناموفقِ بدون پیام سهمیه باعث چرخش حساب نمی‌شود. وضعیت سهمیهٔ علامت‌خورده را می‌توان از صفحهٔ مدیریت حساب‌ها برای تلاش دوباره پاک کرد.

## ورود اصلی GitHub

### یک‌بار برای سازنده یا توزیع‌کنندهٔ اپ

1. سازنده یک‌بار در [GitHub Developer settings](https://github.com/settings/applications/new) یک **OAuth App** ثبت می‌کند: نام دلخواه (مثلاً `CloudPath VPN`) و برای Homepage و Callback یک URL معتبر مانند آدرس همین مخزن وارد کنید. در تنظیمات همان OAuth App گزینهٔ **Enable Device Flow** را فعال کنید. استفاده از توکن‌های دارای انقضا پشتیبانی می‌شود و نیازی به غیرفعال‌کردن انقضای توکن نیست.
2. در تنظیمات این مخزن از مسیر **Settings → Secrets and variables → Actions → Variables → New repository variable** یک variable با نام دقیق `CLOUDPATH_GITHUB_CLIENT_ID` و مقدار **Client ID عمومی** همان OAuth App بسازید. این شناسه متعلق به اپ است، نه حساب ورود نهایی؛ همهٔ کاربران می‌توانند از آن برای ورود به حساب خودشان استفاده کنند. Client ID رمز نیست؛ **Client Secret را وارد اپ، مخزن یا چت نکنید**.
3. پس از تنظیم variable، build را در GitHub دوباره اجرا کنید؛ تغییر variable به‌تنهایی build جدیدی آغاز نمی‌کند. اگر APK بدون شناسه ساخته شود، artifact آن `cloudpath-vpn-debug-unconfigured` نام می‌گیرد و برای ورود در نصب تازه قابل استفاده نیست؛ اپ از کاربر نهایی شناسه نمی‌خواهد، بلکه اعلام می‌کند سازنده باید نسخهٔ پیکربندی‌شده را ارائه کند. تنظیم variable شکل شناسه را بررسی می‌کند، نه واقعی‌بودن OAuth App یا فعال‌بودن Device Flow را؛ ورود واقعی باید آزمایش شود.

### برای هر کاربر اپ

1. ورود GitHub را بزنید، کد را فقط در `github.com/login/device` وارد کنید و با **هر حساب دلخواه خودتان** وارد شوید. رمز عبور در اپ وارد نمی‌شود و نیازی به فرستادن کد یا توکن در چت نیست. برنامه مجوزهای `repo` و `workflow` می‌خواهد: اینها دسترسی گستردهٔ خواندن و نوشتن به مخازن خصوصی و workflowها و برخی منابع سازمانی مانند پروژه‌ها، دعوت‌ها و عضویت تیمی می‌دهند، نه فقط به مخزنی که بعداً ساخته می‌شود. پیش از تأیید، نام اپ و دامنهٔ صفحه را بررسی کنید و اگر با این سطح دسترسی موافق نیستید، ادامه ندهید.
2. پس از ورود، اپ پیش از ساخت مخزن تأیید جداگانه می‌گیرد؛ سپس مخزنی خصوصی با نام تصادفی `cloudpath-vpn-…` در حساب واردشده می‌سازد و فایل‌های لازم را از خود APK در شاخهٔ پیش‌فرض آن نصب می‌کند. مخزن‌های موجود عمداً بازنویسی نمی‌شوند. فایل متفاوت در یک نصب نیمه‌تمام نیز بازنویسی نمی‌شود و نیاز به بررسی دارد. تلاش مجدد پس از قطع شبکه همان نصب نیمه‌تمام را ادامه می‌دهد؛ از تنظیمات حساب می‌توان وضعیت نصب نیمه‌تمام را فراموش کرد و پس از تأیید، نصب تازه‌ای ساخت، ولی مخزن نیمه‌تمام در GitHub خودکار حذف نمی‌شود.
3. کشور را انتخاب و اتصال را با دکمهٔ شروع آغاز کنید؛ اندروید ممکن است تأیید VPN بخواهد. اگر ورود را از دکمهٔ شروع آغاز کرده باشید، پس از آماده‌سازی و اجازهٔ VPN همان درخواست ادامه می‌یابد؛ ورود از بخش حساب به‌تنهایی VPN را روشن نمی‌کند. سهمیه، پرداخت، فعال‌بودن Actions و محدودیت‌های سازمانی به حساب/مالک **همان مخزن انتخاب‌شده** مربوط است. در تنظیمات حساب، انتخاب مخزن آمادهٔ دیگری نیز به‌صورت دستی ممکن است؛ در آن صورت مالک و سهمیهٔ همان مخزن ملاک‌اند و workflow باید روی شاخهٔ پیش‌فرضش موجود باشد. در صورت منع دسترسی نوشتن `GITHUB_TOKEN`، تنظیمات **Actions → General → Workflow permissions** مخزن نیز باید نوشتن محتوا را مجاز کند.

توکن‌های OAuth هر حساب و در صورت صدور، توکن تمدید آن، با کلید Android Keystore رمزگذاری و در کلید ذخیره‌سازی جداگانه نگهداری می‌شوند؛ نسخهٔ پشتیبان اندروید برای اپ غیرفعال است. در به‌روزرسانی از نسخهٔ تک‌حسابی، توکن و runهای قدیمی به حساب فعال همان نسخه نسبت داده می‌شوند. در صورت انقضای access token، برنامه با device flow و بدون Client Secret برای تمدید تلاش می‌کند؛ لغو مجوز، انقضای refresh token یا خطای شبکه ممکن است ورود دوباره بخواهد. «حذف حساب از این دستگاه» فقط توکن و تنظیمات همان حساب را پاک می‌کند؛ سایر حساب‌ها باقی می‌مانند و مجوز OAuth App در GitHub لغو یا مخزن خصوصی حذف نمی‌شود. پیش از حذف اپ ابتدا Stop و پایان نشست را بررسی کنید؛ برای پاک‌سازی کامل، مخزن را در GitHub حذف و در صورت تمایل مجوز OAuth App را از تنظیمات GitHub لغو کنید. تا زمانی که پایان runهای همان حساب تأیید نشده، حذف حساب یا تغییر مخزنش محدود می‌شود.

## وقتی DNS شبکه جواب نمی‌دهد

اگر بعد از تأیید ورود در مرورگر، اپ پیام `Unable to resolve host "github.com": No address associated with hostname` می‌داد، یعنی DNS همان شبکه نام GitHub را برنگردانده است — نه اینکه GitHub در دسترس نباشد؛ همان لحظه صفحهٔ GitHub در مرورگر باز شده بود. اکنون:

- نام‌های ثابت خود اپ (`github.com` و `api.github.com`) در صورت شکست DNS دستگاه با **DNS-over-HTTPS** و از طریق آدرس IP خود سرویس‌دهنده (`1.1.1.1`، `8.8.8.8` و همتایانشان) پرسیده می‌شوند؛ این کار خودش نیازی به resolve ندارد و درست همان جایی کار می‌کند که DNS دستگاه نابیناست.
- درخواست بعد از آن با TLS به همان IP فرستاده می‌شود، اما SNI، هدر `Host` و بررسی گواهی همه با نام واقعی انجام می‌شوند (افزون بر بررسی میزبان پیش‌فرض اندروید). پس پاسخ DNS نادرست یا جعلی تنها می‌تواند اتصال را ناموفق کند و نمی‌تواند توکن را به سرور دیگری بفرستد. هر بار فقط یک درخواست به آن نام‌ها پرسیده می‌شود؛ هیچ دامنهٔ دیگری به سرویس‌های ثالث نمی‌رود.
- اگر DNS-over-HTTPS هم مسدود باشد، اپ به روال عادی برمی‌گردد و پیام فارسی روشن نمایش می‌دهد (به‌جای متن انگلیسی سوکت) و راهنمایی می‌کند VPN/DNS یا شبکه را عوض کنی.
- ورود دیگر با یک خطای موقت شبکه لغو نمی‌شود: کد ورود تا پایان اعتبار خودش دوباره پرسیده می‌شود و فقط پس از چند شکست پی‌درپی متوقف می‌شود.
- همین روش برای نام رله‌ها هنگام اتصال هم به کار می‌رود، چون موتور بومی هم همان DNS دستگاه را دریافت می‌کند. اگر همهٔ راه‌ها بی‌پاسخ بمانند، اتصال به همان مسیر قبلی (نام میزبان) برمی‌گردد.

این روش فقط مشکل «نام پیدا نشد» را حل می‌کند؛ اگر شبکه خودِ TLS به GitHub را قطع یا کند کند، باز هم VPN یا DNS دیگر لازم است. آزمون‌های تجزیهٔ پاسخ DNS و پیام‌های خطا در `android/app/src/test/` هستند.

## اگر پس از قطع، دکمهٔ شروع برنگشت

نسخه‌های پیشین وضعیت نشست را فقط روی دیسک نگه می‌داشتند: اگر اپ بسته یا سرویس توسط اندروید متوقف می‌شد، وضعیت `در حال قطع` یا `متصل` باقی می‌ماند و دکمهٔ بزرگ دیگر کاری نمی‌کرد. اکنون:

- فقط تا زمانی که سرویس واقعاً کار می‌کند وضعیت «فعال» پذیرفته می‌شود؛ در اولین نمایش صفحه، اگر وضعیتی جز «stopped» بدون سرویسِ زنده باقی مانده باشد، اپ آن را به «stopped» برمی‌گرداند و دکمهٔ شروع دوباره کار می‌کند.
- پایان سرویس (از جمله وقتی اندروید آن را متوقف می‌کند) همیشه وضعیت «stopped» را ذخیره می‌کند؛ دیگر وضعیت‌های قدیمی روی دستگاه جا نمی‌مانند.
- اگر نشستی در GitHub تأیید نشده باشد، همان پیام گفته می‌شود و از «تنظیم مخزن و حساب → بررسی و پایان نشست‌های قبلی» می‌توان آن را بررسی کرد.
- تلاش برای لغو runها در زمان قطع حداکثر حدود ۴۵ ثانیه طول می‌کشد تا رابط در حالت «در حال قطع» گیر نکند؛ هر run تأییدنشده برای تلاش بعدی ثبت‌شده می‌ماند. اگر هیچ runی ثبت نشده باشد، قطع فوراً تمام می‌شود.

## ساخت APK آزمایشی

سورس اندروید نیازمند **Android SDK 35، JDK 17 و Gradle 8.9** است. کتابخانه‌های بومی از نسخه‌های مشخص‌شدهٔ libXray و hev-socks5-tunnel دریافت می‌شوند و SHA-256 آنها پیش از استفاده بررسی می‌شود؛ فایل‌های باینری در مخزن قرار نمی‌گیرند. Gradle عامل و workflow همین checkout را در assets اپ بسته‌بندی می‌کند؛ برای راه‌اندازی حساب‌های دیگر دسترسی به مخزن خصوصی نویسنده لازم نیست.

### با GitHub Actions

workflow **Build Android app** برای تغییرات PR اجرا می‌شود و در صورت موفقیت artifact حاوی `app-debug.apk` تولید می‌کند؛ نام آن با تنظیم Client ID برابر `cloudpath-vpn-debug` و بدون آن دارای پسوند `-unconfigured` است. برای اجرای دستی از **Actions → Build Android app → Run workflow**، فایل workflow باید در شاخهٔ پیش‌فرض GitHub موجود باشد. یک PR باز را می‌توان بدون ادغام، با اجرای build مربوط به همان PR بررسی کرد. نصب APK آزمایشی ممکن است نیازمند اجازهٔ نصب از منبع ناشناس در اندروید باشد.

این نسخه به اندروید ۱۰ (API 29) یا بالاتر نیاز دارد، چون کتابخانهٔ بومی شبکه از نسخه‌های پایین‌تر پشتیبانی اعلام نکرده است. APK با کلید debug امضا می‌شود و برای انتشار عمومی مناسب نیست. امضای buildهای جداگانهٔ GitHub ممکن است متفاوت باشد؛ برای نصب build جدید ممکن است لازم شود ابتدا نصب قبلی را حذف کنید که داده‌های محلی آن را نیز پاک می‌کند. پیش از حذف، نشست‌ها را قطع و پایان آن‌ها را بررسی کنید. اجرای build نیز ممکن است از سهمیهٔ Actions استفاده کند. صرف وجود workflow یا PR به معنی موفق‌شدن build و ساخته‌شدن APK نیست.

### روی کامپیوتر توسعه

```bash
# شناسهٔ عمومی OAuth App؛ بدون آن APK برای ورود آماده نیست.
export CLOUDPATH_GITHUB_CLIENT_ID="YOUR_PUBLIC_CLIENT_ID"
cd android
./scripts/fetch-native.sh
gradle --no-daemon testDebugUnitTest assembleDebug
# app/build/outputs/apk/debug/app-debug.apk
```

## رفتار اتصال و محدودیت‌ها

- گزینهٔ «حداکثر سرعت» از آدرس خود رانر استفاده می‌کند. کشور انتخابی فقط وقتی فعال می‌شود که خروجی VPN Gate برای همان کشور آماده باشد و سرویس مکان‌یابی، همان کشور را گزارش دهد. فهرست کشورها به معنی تضمین وجود سرور نیست؛ ممکن است کشور انتخاب‌شده در دسترس نباشد یا مکان‌یابی اشتباه باشد. هنگام اتصال برای تغییر کشور ابتدا قطع کنید.
- برای جلوگیری از سقوط بی‌صدا به خروجی رانر، اپ برای کشور انتخاب‌شده فقط VPN Gate را درخواست می‌کند؛ مسیر Psiphon موجود در عامل قدیمی برای این اپ استفاده نمی‌شود چون UDP آن از خود رانر خارج می‌شود. با این حال، تشخیص کشور و جلوگیری از نشت در همهٔ شرایط تضمین‌شده نیست.
- سرورهای عمومی VPN Gate گاهی اتصال یا احراز هویت را رد می‌کنند (`AUTH_FAILED`). عامل اکنون تا ۲۴ میزبانِ برترِ دو رتبه‌بندی را در یک بازهٔ محدود بررسی می‌کند؛ اگر باز هم هیچ‌کدام نپذیرفتند، مسیر را بی‌صدا به خروجی مستقیم یا کشور دیگری تغییر نمی‌دهد. کمی بعد دوباره تلاش کن یا «حداکثر سرعت»/کشور دیگری را انتخاب کن. اگر پیام پایان نشست GitHub هنوز تأیید نشده دیدی، از تنظیمات حساب گزینهٔ بررسی و پایان نشست‌های قبلی را اجرا کن.
- پس از درخواست Start، آماده‌شدن نشست و خروجی ممکن است چند دقیقه طول بکشد. اپ پیش از نشان‌دادن اتصال، مسیر رمزگذاری‌شدهٔ وضعیت را از داخل پروکسی بررسی می‌کند؛ این بررسی تضمین نمی‌کند که همهٔ سایت‌ها یا خروجی انتخابی همیشه در دسترس باشند.
- Stop اتصال گوشی را قطع می‌کند و تلاش می‌کند **فقط runهای همین اپ** را در GitHub لغو کند. اگر اینترنت یا GitHub در دسترس نباشد، قطع‌شدن run سمت GitHub تضمین نمی‌شود؛ شناسه برای تلاش مجدد نگهداری می‌شود و پیام هشدار نمایش داده می‌شود. در صورت لزوم run را در بخش Actions به‌صورت دستی لغو کنید.
- وقتی VPN قطع می‌شود، اندروید ممکن است اینترنت را مستقیم برقرار کند. در صورت نیاز به جلوگیری از عبور مستقیم، در تنظیمات سیستم اندروید «Always-on VPN» و «Block connections without VPN» را بررسی کنید؛ رفتار آن بسته به دستگاه متفاوت است.
- دسترسی به رانر از رله‌های عمومی یا Cloudflare Quick Tunnel استفاده می‌کند؛ این سرویس‌های ثالث ممکن است در شبکهٔ شما قطع، فیلتر یا کند باشند. نسخهٔ اندروید از VMess AEAD داخل WebSocket استفاده می‌کند تا محتوای جریان برای رلهٔ خاتمه‌دهندهٔ TLS آشکار نباشد؛ VMess محرمانگی پیشرو (forward secrecy) ندارد و رله همچنان IP، زمان و حجم اتصال را می‌بیند. این پروژه حسابرسی امنیتی یا آزمون کامل روی گوشی واقعی نشده است.
- سیستم اندروید ممکن است سرویس پس‌زمینه را متوقف کند، محدودیت باتری اعمال کند یا اجازهٔ اتصال را پس بگیرد. هیچ تضمینی برای اتصال همیشگی یا ناشناس‌ماندن وجود ندارد.

## ساختار و آزمون

- `agent/`: عامل رانر، مدیریت کشور، رله‌ها و رمزگذاری اطلاعات نشست. رفتار پیش‌فرض VLESS برای کلاینت اصلی حفظ شده؛ workflow جدید اندروید VMess را انتخاب می‌کند.
- `android/`: اپ، رابط کاربری و سرویس `VpnService`، ورود OAuth، آماده‌سازی مخزن خصوصی، مدیریت و لغو runها و دریافت کتابخانه‌های بومی.
- `.github/workflows/github-vpn-session.yml`: اجرای یک نشست آزمایشی؛ `.github/workflows/build-android.yml`: آزمون و ساخت APK.
- `tests/` و `android/app/src/test/`: آزمون تنظیمات عامل، نصب ایمن مخزن برای هر حساب، رمزنگاری، اعتبارسنجی رله و انتخاب کشور.

اجرای آزمون‌های Node بدون نصب وابستگی:

```bash
node --test tests/*.test.mjs
```

مجوزهای کتابخانه‌های استفاده‌شده در `android/app/src/main/assets/licenses/` همراه APK بسته‌بندی می‌شوند.
